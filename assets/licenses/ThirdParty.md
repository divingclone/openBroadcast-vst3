# Third-party components and provenance

- OpenBroadcast: source references `../openbroadcast/src/openbroadcast/audio/denoiser.py` and `studio.py`; original 48 kHz analysis/synthesis windows and mel matrix from `data/dsp_48k.npz`; `denoiser_48k.onnx`, `dereverb_48k.onnx` and `studio_voice_48k.onnx` copied without modifications. `src/vendor/explicit_dml.cpp` imports the upstream native DirectML helper, retaining GPU-resident streaming state; its export macro is adapted for static linking. The upstream source describes the models as extracted from NVIDIA Broadcast. No new license to NVIDIA model weights is granted by this project. Asset hashes are recorded in the bundle's `Contents/Resources/manifest.json`.
- JUCE 8.0.12, commit `29396c22c93392d6738e021b83196283d6e4d850`: JUCE's AGPLv3/commercial licensing terms apply. License copied to `Contents/Resources/licenses/JUCE.md`. This project does not claim a commercial JUCE license.
- KissFFT 131.1.0, commit `8f47a67f595a6641c566087bf5277034be64f24d`: BSD-3-Clause. License copied to `Contents/Resources/licenses/KissFFT.txt`.
- ONNX Runtime 1.24.4 (Windows DirectML / Linux CUDA or CPU), 1.27.1 (Linux AMD MIGraphX, using the backward-compatible 1.24 C API) and 1.23.2 (macOS arm64 with CoreML): MIT and included third-party notices, copied to `Contents/Resources/licenses/`. SDK/wheel versions and SHA-256 digests are pinned in the build scripts. The AMD package extracts the native core and provider libraries from the `onnxruntime-migraphx` wheel without its Python binding. Linux acceleration additionally uses system driver and compute libraries: NVIDIA CUDA/cuDNN or AMD ROCm/HIP/MIGraphX, which are not bundled.
- Microsoft DirectML 1.15.4: Microsoft package license and code license, copied to `Contents/Resources/licenses/`.

NVIDIA and NVIDIA Broadcast names identify the source technology. This independent implementation is not affiliated with or endorsed by NVIDIA.

Cross-platform backend selection follows OpenBroadcast's `audio/inference.py` and `audio/denoiser.py`: CUDA driver ordinals and compute/memory ranking on Linux; system-managed CoreML `CPUAndGPU` on macOS; CUDA convolution search uses `HEURISTIC`.
The unified Linux x64 bundle shares models between separate CUDA and MIGraphX worker processes, keeping their ONNX Runtime versions and provider dependencies isolated. HIP device discovery preserves native ordinals and prefers discrete GPUs. HIP scalar attribute identifiers follow `ROCm/HIP`'s `hip_runtime_api.h`; no HIP structure layout is copied or assumed.
